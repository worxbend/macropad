# The microsite

One long page about the macropad, published at <https://worxbend.github.io/macropad/> by
`.github/workflows/pages.yml` on every push to main. It is plain HTML, CSS and JavaScript:
no npm, no bundler, no framework, no third-party scripts. The only outside request is the
Archivo font from Google Fonts.

| File | What it is |
|---|---|
| `index.html` | The page: every section, every caption, every alt text. |
| `style.css` | Colours, type, layouts, and the sticky stages of the scroll scenes. |
| `motion.js` | Scroll scenes, the debug hooks, and the four widgets (finishes, board views, layer tabs, demo). |
| `shots.sh` | Headless Firefox screenshots, used by `make site-shots`. |
| `README.md` | This file. It is not published. |

## How the page is built

`make site` runs `.github/scripts/build_site.py`. It builds into `_site.staging/` and moves the
result to `_site/` only when every check passes (`make site-serve` uses `_site.staging-serve/`, so
the two can run at once). It:

- copies the `.html`, `.css`, `.js` and `.svg` files of this folder;
- copies every picture a page names as `images/<group>/<file>` from `docs/images/<group>/<file>`;
- draws the signature from the Bezier chains in `cad/macropad_case/signature.py`, read with Python's
  `ast` module, writes it to `images/signature.svg`, and inlines it where `index.html` has the
  comment `<!-- signature:svg -->`. The page and the laser file share one source;
- writes resized WebP copies of the case and board renders when Pillow is installed (CI installs
  it). Without Pillow the `<source type="image/webp">` lines are removed and the PNGs are used;
- makes a silhouette of the parts in `docs/images/cad/exploded.png` and puts it into `style.css`
  where it says `url(images/exploded-mask.png)`, as a `data:` URL. The exploded scene masks its moving
  slices with it. It is inlined because browsers fetch mask pictures with CORS, which fails for a
  page opened from `file://`. The mask is cached in `.build/site-mask/` until the render changes.

The pictures in `docs/images/` are generated by `make cad`, `make pcb-place` and `make ui-images`.
Never edit them by hand, and never copy them into this folder: name them from the page instead.

## The fast loop

```bash
make site-serve              # build, serve http://127.0.0.1:8000/, rebuild on every change
make site-serve SITE_PORT=8080
make site-shots              # screenshots into .build/site-shots/ (SHOTS=dir to change)
```

`make site-serve` watches this folder, `docs/images/`, `signature.py` and the top-level `README.md`
(its headings are link targets). A rebuild that fails prints its problems and keeps serving the
last good build. After editing `build_site.py` itself, stop the server and start it again.

`make site-shots` shoots whole pages in chunks of a few sections (`?motion=off&only=...`, no window
taller than 10000 px), the scroll scenes at chosen progress, the signature's end state at
320 x 568, 844 x 390 and 768 x 1024 (short screens get the static layout), and the first 12000 px
of the page with JavaScript off. It runs one Firefox at a time at low priority.

Scroll scenes cannot be screenshotted by scrolling, so `motion.js` reads debug parameters:

| Parameter | Effect |
|---|---|
| `?frame=0.5` | Every scene held at progress 0.5. Scrolling is ignored. |
| `?frame=light:0.3,hero:1` | Named scenes at the given progress. |
| `?only=signature,specs` | Every other section hidden; the header stays. |
| `?motion=off` | The reduced-motion page: no scroll scenes, every scene in its final state. The widgets (finishes, board views, layer tabs, demo) still work. For the page without JavaScript, turn scripts off in the browser. |
| `?debug=bands,sigbox,width,errors` | Outline the exploded bands or the signature's target box, list anything wider than the window, print script errors on the page. |

Scene ids: `hero`, `words`, `design`, `light`, `colourways`, `details`, `exploded`, `inside`,
`board`, `firmware`, `signature`. For one shot: `site/shots.sh /tmp/shots "sig:1440:900:?only=signature&frame=signature:0.6"`.

## Adding a section

1. Add a `<section id="...">` inside `<main>` with an `h2`, and keep the heading levels in order.
2. Name pictures as `images/cad/x.png`, `images/pcb/x.png` or `images/ui/x.png`.
3. Give every `img` a `width`, a `height`, an `alt` that describes what the render shows, and
   `loading="lazy"`. For a case or board render, add a `<source type="image/webp">` line with
   800 px and full-width copies, as the other pictures do.
4. If it moves, register a scene in `motion.js` whose update writes only `transform` and `opacity`,
   give the scene a readable static layout in `style.css` first, and check frames 0 and 1 with
   `?frame`. Use-case, spec, status and build sections do not move.
5. Add a header link if the section matters.

## The checks

`make site` fails when:

- a page or a stylesheet names a picture that is not in `docs/images/`, or a WebP copy wider than
  its PNG;
- a picture (PNG, GIF, JPEG or WebP, any letter case, any depth) in `docs/images/cad`,
  `docs/images/pcb` or `docs/images/ui` is not shown on any page. Shown means an `<img src>`, a
  WebP `<source>` in the same `<picture>` as that `img`, a stylesheet `url()`, or the demo's
  `data-gif`; a plain link or the `og:image` does not count. Show it, or add it to `SKIP` in
  `build_site.py` with a one-line reason;
- a `SKIP` entry names a missing file, a file that is shown anyway, or has no one-line reason;
- a local link, picture or `#anchor` does not resolve in `_site/`, or an id is used twice. Links to
  `https://worxbend.github.io/macropad/` (the `og:image`) and `url()` in stylesheets count as local;
- a link to `github.com/worxbend/macropad/blob/main/...` or `/tree/main/...` names a path that is
  not in the checkout, or a `#anchor` on the repository link has no heading in `README.md`;
- an image lacks `width`, `height` or `alt`, its `width` and `height` are not the picture's own
  pixel size (a re-render with a new size must update the page, or the page reserves the wrong
  box), an empty alt is not inside `aria-hidden="true"`, or an image after the first is not lazy;
- the page has more or fewer than one `h1`, or a heading skips a level;
- the signature cannot be read from `signature.py`, its placeholder is not in the page once, or no
  page shows its caption (Signature Edition);
- a WebP `<source>` is not on a line of its own (without Pillow those lines are removed);
- no stylesheet uses the exploded-view mask;
- the build's own self-check of its patterns and writers fails.

## Rules

- Every claim must be true for this design. No wireless, no battery, no app, no VIA or QMK.
  Keymaps change by editing Rust and flashing a UF2.
- Nothing has been built, printed, milled or switched on. The header pill, the hero, the captions
  and the status section say so. Keep them.
- The signature's lettering is the owner's. Do not restyle it.
- Respect reduced motion: the page must read completely with `?motion=off` and with JavaScript off.
